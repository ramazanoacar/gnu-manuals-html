#### Footnotes

##### [(1)](#DOCF1)

`texi2any` can handle non ASCII characters
in input file names, but non ASCII characters in output name will create
problems for some output formats, especially for cross-references.

##### [(2)](#DOCF2)

We have found
that it is helpful to refer to versions of independent manuals as
‘editions’ and versions of programs as ‘versions’; otherwise, we find we
are liable to confuse each other in conversation by referring to both
the documentation and the software with the same words.

##### [(3)](#DOCF3)

Prior to the Texinfo 5 release in 2013, this feature was supported in
an ad hoc way (the `--commands-in-node-names` option to
`makeinfo`). Now it is part of the language.

##### [(4)](#DOCF4)

In TeX output, `@var` currently uses a
slanted typewriter font in code contexts such as `@code`
or `@example`. We plan to change this in the next release to
use a variable-width, slanted roman font in all contexts. To avoid
this change, set the ‘`txicodevaristt`’ flag using `@set`;
specify ‘`@clear txicodevaristt`’ to make this change now
(see [`@set` and `@value`](#g_t_0040set-_0040value)). Note that this flag does nothing in
LaTeX output.

##### [(5)](#DOCF5)

A footnote should complement or expand upon the
primary text, but a reader should not need to read a footnote to
understand the primary text. For a thorough discussion of footnotes,
see The Chicago Manual of Style, which is published by the
University of Chicago Press.

##### [(8)](#DOCF8)

`texi2any` supports more encodings for Texinfo

output.
